# 2026-09-28-ci-cd GitHub Actions CI/CD

Date: 2026-09-28 · Requirements: T1.21, T3.15 (interim), NFR-10 · Agent: ops (main agent)

## What was done
- CI (`.github/workflows/ci.yml`) now also runs the whole Playwright suite on every pull request and push to main. The e2e job:
  - builds the SPA (with the dev gallery on, for summary.spec) into the Go binary and serves it on :8080, as production does;
  - starts Gotenberg as a container that can reach the runner (`--add-host host.docker.internal:host-gateway`);
  - prepares Postgres and Redis like the unit-test job;
  - runs Playwright with the installed Edge. Failed runs upload test-results and the app log.
- CD (`.github/workflows/cd.yml`, new) runs after CI passes on a push to main:
  - builds the app and migration images from that commit;
  - scans both with Trivy (HIGH/CRITICAL with a fix stops the release) before pushing to `ghcr.io/<owner>/<repo>/ticket-app` and `.../ticket-migrate`;
  - makes Syft SPDX SBOMs, signs both images keyless with Cosign, and attaches the SBOMs as attestations;
  - writes the new digests into `deploy/overlays/staging/kustomization.yaml` and commits that to main with `[skip ci]`.
  Argo CD (T3.14) will sync staging from there.
- Playwright can test an app that is already running: `E2E_BASE_URL` switches the base URL and turns off the Vite/`go run` web servers. Specs take `baseURL` from e2e/helpers.ts instead of a hard-coded `localhost:5173`. `make serve-built` runs the app the way CI does.

## Decisions
The user chose four of these (2026-09-28); the rest were made without asking.
- User's choice: GHCR now, Harbor later. The registry is the `REGISTRY` env and the login step in cd.yml; switch both in T3.12. The deploy rule "images only from Harbor" and the Kyverno policy (T3.12) must allow GHCR until then, or Harbor must mirror.
- User's choice: the staging digests are committed to this repo's overlay, not a separate GitOps repo. Reverse by pushing to the GitOps repo in the last CD step once T3.14 creates it.
- User's choice: the e2e job is added to CI, against the built app.
- User's choice: Cosign signs keyless with GitHub's OIDC identity; no key to store. Kyverno should verify the issuer `https://token.actions.githubusercontent.com` and this repo's workflow as the subject.
- By digest, not tag, in staging, so staging runs exactly the signed image.
- The GitHub token's push starts no workflow run, so the digest commit cannot loop; `[skip ci]` makes that visible in history.
- One retry for e2e in CI only: under full-suite load `live.spec`'s 2 s budget and Gotenberg prints can miss. They then show as flaky in the report instead of failing the build.
- No ZAP stage and no Vault yet (no staging, no Vault). No production step: prod is promoted by hand, as planned.
