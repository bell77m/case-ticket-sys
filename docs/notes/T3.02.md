# T3.02 Written summary

Date: 2026-09-25 · Requirements: FR-P1, FR-I5, FR-I6 · Agent: fe (+ i18n-translator)

## What was done
- A written summary for the reports dashboard: up to six plain sentences built from fixed message templates (no AI), in the viewer's language. They cover tickets opened and resolved in the period, the change against the previous period, what was still open at the period end (unassigned, urgent), the median first response and resolution times, and the busiest building and most common category.
- `writtenSummary(report)` reads the T3.01 response (`GET /api/staff/reports`) and fills Paraglide `summary_*` messages. Numbers and dates use `Intl` in the active locale; durations use `Intl.NumberFormat` units (minutes under 2 h, hours under 48 h, days above). Null medians and empty periods get their own sentences.
- English plurals use Paraglide 2 variants (`plural` selector); zh-CN, my and th use plain strings, as those languages have no grammatical plural.
- `WrittenSummary` shows the sentences in a card. It is in the /dev/components gallery with a fixed sample report; the dashboard page itself is T3.03.
- No backend change: the report API already returns every number, and the PDF (T3.05) will render the same frontend page, so one generator serves both.

## Decisions
- Frontend only, although the plan says be + fe: the sentences are built in the browser from the existing report JSON. Reverse by moving the templates server-side if a non-browser consumer ever needs them.
- The "no tickets" sentence shows only when new, open and resolved are all 0 (resolved can be above 0 when new and open are 0).
- The change sentence compares new tickets only, with three separate keys (up, down, same) so word order can differ per language.
- Durations switch units at 2 hours and 48 hours.
