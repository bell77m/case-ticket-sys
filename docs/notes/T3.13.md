# T3.13 Kustomize manifests

Date: 2026-09-27 · Requirements: none (ops; NFR-7 and NFR-10 constraints respected) · Agent: ops

## What was done
- `deploy/base` describes the whole app for Kubernetes: the ticket-app Deployment (2 replicas, `/healthz` readiness and liveness probes, non-root, read-only root filesystem, CPU and memory limits, uploads on a PVC), PostgreSQL 16 and Redis 7 StatefulSets with volumes, Gotenberg 8, their Services, and a goose migration Job.
- `deploy/overlays/staging` and `deploy/overlays/prod` set the namespace, image tags, `BASE_URL` and (prod) larger volumes: uploads 200Gi, PostgreSQL 50Gi.
- Every pod reads secrets from one Secret, `ticket-app-secrets`, which VSO will create from Vault (T3.11). The keys it must hold are listed in `deploy/base/kustomization.yaml`; no secret value is in Git.
- Argo CD order on every sync: wave 0 (PostgreSQL, Redis, Gotenberg, ConfigMaps) becomes healthy, then the migration Job runs as the owner role `ticket` (wave 1), then the app rolls out (wave 2).
- `make deploy-lint` renders both overlays and runs kube-linter and Trivy config on them from Docker images.

## Decisions
- Migrations run as a Sync hook in wave 1, not a PreSync hook as the plan said. A PreSync hook runs before PostgreSQL exists on a new namespace's first sync, so the first sync would fail. To go back: set `argocd.argoproj.io/hook: PreSync` in `migrate-job.yaml` and remove the wave annotations; the first sync then needs a manual PostgreSQL-only sync.
- Separate migration image (`deploy/migrate.Dockerfile`) instead of adding goose to the app image. This keeps the app image small. To reverse: copy goose and the migrations into the main Dockerfile and point the Job at the app image.
- Uploads PVC is ReadWriteOnce: T3.09 is one k3s node with local-path storage. A second node needs an NFS (ReadWriteMany) storage class (docs/ARCHITECTURE.md, Uploads).
- Third-party images (postgres, redis, gotenberg) pull through a Harbor Docker Hub proxy project, because images may come only from Harbor (.claude/rules/deploy.md). The Harbor host `harbor.example.internal` and the prod host `tickets.example.internal` are placeholders.
- `APP_ENV` is not set: the app does not read it.
