# T3.01 Reports API

Date: 2026-09-24 · Requirements: FR-P1, FR-P2 · Agent: be

## What was done
- `GET /api/staff/reports`, behind report.view, returns the data for the dashboard:
  - 7 summary cards (open, unassigned, urgent open, new, resolved, median first response, median resolution), each with its value for the previous period of equal length
  - all 7 graph datasets: opened vs resolved per day, open by status, open by priority, by category, by location (building → floor → line tree), staff workload by priority, and weekly medians
- Filters apply to every number:
  - `from`/`to` (inclusive dates; default the last 30 days; at most 366 days)
  - `tz` (IANA name from the browser, checked against PostgreSQL's time zone list; default UTC)
  - `building` (English name)
  - `category_id`
  - `lang` picks the language for names
- Open, unassigned and urgent open are counted as of the end of the period: each ticket's status, priority and assignee are rebuilt from audit_log. A ticket closed today still counts as open for last week.
- All date math and medians run in PostgreSQL (`AT TIME ZONE`, `generate_series`, `percentile_cont`).

## Files
- backend/internal/api/reports.go (new): handler, input checks, SQL for the cards and datasets.
- backend/internal/api/reports_test.go (new): fixed March 2020 data under a unique test building.
- backend/internal/api/api.go: the route, behind `require(rbac.ReportView)`.

## Decisions
- "Open", "Unassigned" and "Urgent open" are counted as of the period end, rebuilt from audit_log. The other cards count what happened inside the period. Reverse: count them from the tickets' current status instead.
- Category and building filters use the ticket's current category and location, not their history.
- "Resolved" uses the current `resolved_at`, so a ticket that was reopened drops out.
- Medians are seconds as floats (percentile_cont interpolates between two values).
- Dates before 2000 are refused. A missing `to` means today; a missing `from` means `to` minus 29 days.
- No new index: EXPLAIN on the dev DB showed the existing `audit_log(ticket_id)` index is enough (4.5 ms).
