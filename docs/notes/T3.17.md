# T3.17 End-to-end smoke tests (local part)

Date: 2026-09-29 · Requirements: FR-G1, FR-G2, FR-G3, FR-T1, FR-T5, FR-P3, FR-I1 (and the T2.14 CSP finding) · Agent: fe (main agent; the CSP config by svelte-frontend)

The task stays open: running the smoke suite in CI against staging waits for T3.15 to deploy a staging environment.

## What was done
- `frontend/e2e/smoke.spec.ts` walks one ticket through its whole life in each of en, zh-CN, my and th, using only the UI in that language:
  - a guest submits the form with a photo;
  - an Agent signs in on /login, assigns the ticket to themselves, sets it In Progress, then Resolved;
  - a Viewer's reports dashboard counts it without a reload;
  - the guest confirms the fix on the tracking link and sees it closed.
- The app now sends `script-src` and `style-src`: `kit.csp` in hash mode (frontend/vite.config.ts). The built index.html carries them as a `<meta>` tag. It allows the one inline bootstrap script by its hash, and the one inline style SvelteKit adds (its hidden route announcer) by hash with `'unsafe-hashes'`. The Go server's header keeps `frame-ancestors`, `object-src`, `base-uri` and `form-action`. Browsers enforce both policies.
- A second test in the same file opens every other page as root (home, queue, the four admin pages, ticket detail, tracking page). It fails on any CSP refusal the browser logs.
- The smoke tests also fail on any CSP refusal on the guest, Agent and Viewer pages.

## Files
- frontend/e2e/smoke.spec.ts (new): the 4-language smoke flow and the CSP page check.
- frontend/vite.config.ts: `csp` in the `sveltekit()` options.
- frontend/src/routes/+page.svelte: the two `style="--delay: …"` attributes became `style:--delay` directives. Svelte sets these through CSSOM, which the CSP allows.
- frontend/src/app.html: the SvelteKit wrapper `<div style="display: contents">` became a plain `<div>`. `body` is a plain block, so layout is unchanged.
- frontend/e2e/helpers.ts, a11y.spec.ts, tracking-page.spec.ts: axe is injected with `page.evaluate(axeSource)` instead of `page.addScriptTag`. The CSP refuses an injected inline script; `evaluate` runs through DevTools.
- backend/cmd/ticket-app/main.go: the `securityHeaders` comment says where script-src and style-src come from (the ponytail note is gone).

## Decisions
- The CSP goes in a `<meta>` tag from the build, not in the Go header, because the script hash changes with every build. Reverse: drop `csp` from vite.config.ts, or have the Go server compute the hash of the embedded index.html at startup.
- SvelteKit's route announcer keeps its inline style, allowed by its exact hash. Blocked, the visually hidden announcer shows on screen after each navigation. A SvelteKit update that changes the style fails the CSP test against the built app, and the browser's message names the new hash.
- The dashboard check filters the reports page to a category created for that run (by root through the API; the Agent sets it with the status change), so its Resolved card goes from 0 to 1 whatever other specs do in parallel. Two earlier versions were flaky under 6 workers, because another spec's change cancelled ours out:
  - "one more than before";
  - "equals the last report fetched".
  Each run leaves 4 deactivated categories behind, as lookups.spec does with locations.
- The Agent (self-assign only) works the ticket, because only that role has the "Assign to me" button. The Viewer watches the dashboard (report.view).
- No `default-src` yet: see Follow-ups.

## Checks
- The CSP assertions were run first, against the running app without the change: 5/5 failed on the missing `script-src`.
- Against the built app (`make build` with `VITE_SHOW_DEV_PAGES=1`, the binary on :8081 with `GUEST_TICKET_LIMIT=1000`, `E2E_BASE_URL=http://localhost:8081`), `e2e/smoke.spec.ts` passed 5/5 in 35 s, one worker. The first built run found SvelteKit's announcer style; its hash was added.
- Full suite against the built app, 6 workers: 57 passed, 4 failed, with no CSP refusal anywhere. None of the 4 comes from this change:
  - export.spec "Thai and in Burmese": Gotenberg 503 under load. It passed alone twice (22.6 s, 30.5 s).
  - live.spec "reports dashboard counts a new ticket": the known 2 s budget flake under load. It passed alone.
  - reports.spec:137 "each card opens the queue": another session's uncommitted test, which expects 7 linked cards where the page has 5.
  - layout.spec "queue summary is readable", `my` at 1024px: the summary column is 180 px against a 200 px minimum. It fails the same way (180.28 px) with the CSP bypassed (`bypassCSP: true`), so it predates this change.
- `npm run check`: 0 errors, 0 warnings. `make test-go PKG=./cmd/ticket-app`: TestSecurityHeaders and the rest pass. `node scripts/check-i18n.mjs`: pass.
- The built index.html holds exactly one inline script, and it matches the meta tag's hash.
- Security review (vite.config.ts, app.html, main.go, the built index.html): no blocking finding.
  - The header/meta split is sound.
  - Evidence downloads cannot be used as same-origin scripts: nosniff, content type from magic bytes, and a sandbox CSP.
  - `'unsafe-hashes'` is limited to the one hash.
  - One Low, accepted: no `default-src` (see Follow-ups).
