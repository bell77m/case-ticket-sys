# T3.07 Translations

Date: 2026-09-28 · Requirements: FR-I1, FR-I3 · Agent: i18n-translator

## What was done
- Every screen now reads in Simplified Chinese, Burmese (Unicode) and Thai: all 403 message keys, including statuses, priorities, permissions, error codes, reports, the activity log and the print pages. Before this task 388 keys per language were English placeholders.
- The translations are AI drafts, one agent per language, and still need a native-speaker review (the open question "Who translates and reviews Chinese, Burmese and Thai?" in docs/PLAN.md).
- `scripts/check-i18n.mjs` now also counts values still identical to English. The default run only reports the count, because the project rule still allows English placeholders for new keys. `--strict` fails on them; that is the done criterion.

## Files
- frontend/messages/zh-CN.json: 388 keys translated; 3 older summary keys aligned to the new terms (建筑→楼栋, 开的→新建的).
- frontend/messages/my.json: 385 keys translated; 3 older summary keys aligned ("urgent" as အရေးပေါ်, "median" as အလယ်ကိန်း).
- frontend/messages/th.json: 388 keys translated; `reports_err_range` uses the same words (ตั้งแต่/ถึง) as the date fields.
- scripts/check-i18n.mjs: the placeholder count, `--strict`, and the `sameOK` allowlist (queue_ticket_no, timeline_other, roles_grant).
- CLAUDE.md: see Docs updated.

## Decisions
- Draft translations were made by AI without a native speaker; each needs review before the pilot. Terms the translators flagged:
  - zh-CN: 产线 (line), 提交人 (guest), 超级管理员 (Root Admin), 处理人 (assignee), 未结 (open).
  - my: တင်ကြားချက် (ticket), တင်ကြားသူ (guest), အတွင်းမှတ်စု (internal note), အခန်းကဏ္ဍ (role), ရပ်ဆိုင်း / ပြန်လည်ဖွင့် (deactivate / reactivate), အလယ်ကိန်း (median).
  - th: เป้าหมาย (activity target), เปิดใหม่ (opened), เพิ่มความคิดเห็น (comment added), มัธยฐาน (median).
- The default `check-i18n` does not fail on placeholders, so new keys can still ship with English text as CLAUDE.md allows. To make placeholders fail CI, run it with `--strict` in the Makefile and ci.yml.
- In Burmese, "Root Admin", IT, ID, PDF, QR and MB stay in Latin letters.
- The app's Zawgyi detector flags 11 short Burmese strings; the characters are in Unicode order (false positives, the detector is for user input, not message files).

## Checks
- `node scripts/check-i18n.mjs --strict`: exit 0 (no placeholders outside `sameOK`). All three files parse as JSON.
- `npm run check`: 0 errors (the translators ran it after each batch; `make lint` includes it).
- `make test` (test cache cleared): exit 0, every package ok. `make lint`: exit 0.
- `npm run test:e2e`: two full runs, 53/54 each. Each run had one different Gotenberg print test fail with a 30 s hang:
  - "Export PDF on the activity log downloads it in Thai with the Thai font";
  - then "Gotenberg refuses to print a failed print page".
  `export.spec.ts` alone passed 7/7. The layout tests (no sideways scroll at 320px in all languages) and the axe tests passed in both runs with the real translations.
- Security review: not needed (message text only).
