# T2.15 Username and password sign-in replaces SSO

Date: 2026-09-24 · Requirements: FR-R1, FR-A1, FR-A2, FR-A6–FR-A11, NFR-9 · Agent: be + fe

## What was done
- Staff sign in at /login with a username and password. Entra ID SSO, the dev OIDC provider and the go-oidc and x/oauth2 dependencies are gone. Every failure (unknown username, wrong password, deactivated account, no password set) gets the same 401 `auth.invalid` after one full PBKDF2-SHA256 check, and `login.failed` is audited with the typed username.
- Root Admin creates staff with a username, an optional work email (kept for notifications, T2.12) and a temporary password. Root Admin can also reset any password to a new temporary one (`PUT /api/staff/accounts/{id}/password`).
- With a temporary password the API allows only `me`, the password change and sign-out; everything else gets 403 `auth.password_change_required`. The frontend sends staff to /staff/password until they choose their own password (`POST /api/auth/password`).
- A session remembers the `password_changed_at` it started with. A change or reset ends every older session on its next request. A change that races a reset loses, and the reset stands.
- Redis counts sign-in attempts before the hash check: 5 per username and 20 per IP in 15 minutes, then 429. A right password takes its attempt back, so parallel requests cannot get past the limit.

## Decisions
- Hashing uses the Go standard library PBKDF2 (no new dependency) rather than argon2 or bcrypt. The work factor is stored in each hash, so it can rise later. Reverse: add golang.org/x/crypto and rehash at sign-in.
- Existing staff rows got `username = lower(email)` and no password. Root Admin resets them, or `create-root-admin --force` adds a Root Admin who can.
- Blocked (429) attempts are not audited, so an attacker cannot fill audit_log.
- The session cookie is now SameSite=Strict (there is no IdP redirect back any more).
- zh-CN, my and th hold English for the new keys, like every other key; T3.07 translates them all.
