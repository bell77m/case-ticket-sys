# T3.06 Activity log page

Date: 2026-09-28 · Requirements: FR-L1, FR-L2, FR-L3, FR-I6, FR-R3, FR-P4 · Agent: be + fe

## What was done
- Staff with audit.view (Root Admin, Admin, Team Lead) open "Activity log" from the account menu at `/staff/admin/activity`. Agents and Viewers get the no-permission page, and the API answers 403.
- The log lists every audit_log row, newest first: time, who (staff name, or Guest/System), a translated action with from → to values, ticket link, target and IP address. Filters: staff, action (repeatable), ticket, date range with time zone. They are kept in the URL, with pagination like the queue.
- "Export PDF" downloads `activity-log-YYYY-MM-DD.pdf` (the newest 5000 rows of the filtered log, with a "showing the newest 5000" line when cut). It uses the T3.05 print-token flow, now generalized with a kind: the token key is `print:<kind>:<sha256>`, so a report token cannot open the activity log or the other way round. The export is audited as `activity.exported` before the PDF is sent.
- `GET /api/staff/activity` (audit.view) serves the page. IP address and target (which can hold usernames) appear only on this endpoint and its print twin; the ticket timeline still hides them.

## Decisions
- No new index. On about 10k rows, EXPLAIN uses the existing `audit_log_created_at_idx` (0.4 ms unfiltered, 0.17 ms by date); the total count reads the whole table (1.7 ms). Add `audit_log(created_at DESC, id DESC)` if the log grows large.
- The staff filter uses what the viewer can already read: all accounts with staff.manage, otherwise active staff from assignees (ticket.assign), otherwise a numeric staff ID field. No backend change.
- Print times use the export's time zone, because Gotenberg runs in UTC.
- The Thai activity-log export test lives in export.spec.ts, because Gotenberg prints one page at a time and prints from two parallel spec files queued past its 30 s limit.
- The export cap is 5000 rows (a package variable in activity.go).
