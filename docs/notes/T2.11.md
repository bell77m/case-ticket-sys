# T2.11 Admin: categories and locations

Date: 2026-09-24 · Requirements: FR-I4, FR-R3, FR-L1 · Agent: be + fe

## What was done
- Staff with category.manage (Root Admin, Admin, Team Lead) can add, rename, deactivate and reactivate ticket categories and locations at `/staff/admin/lookups`, reached from the account menu. Nothing is deleted; deactivated rows vanish from the guest form but stay on the admin page.
- Every name is entered in all four languages (en, zh-CN, my, th), each input tagged with its `lang`. The API refuses a request that leaves any language empty (FR-I4 as written).
- A location row is one building + floor + line, as in the schema. "Add line" picks an existing building and floor (their names are copied) or creates new ones.
- API, all behind `require(category.manage)` and audited in the same transaction: `GET/POST /api/staff/categories`, `PATCH /api/staff/categories/{id}`, `GET/POST /api/staff/locations`, `PATCH /api/staff/locations/{id}`. Audit actions: category.created/changed/deactivated/reactivated and location.created/changed/deactivated/reactivated.
- The public `GET /api/categories` and `GET /api/locations` are unchanged: active rows only, one language, English fallback.

## Decisions
- All four languages are required on every name, following FR-I4 literally. An admin who lacks a translation must type something (for example the English name). To relax it, drop the non-English keys from the required check in `checkNames` in admin_lookup.go; the public endpoints already fall back to English.
- A duplicate location is the same English building / floor / line, ignoring case. That is stricter than the DB `UNIQUE (building, floor, line)`, which compares whole JSONB values and would let one place in twice with different translations. Reverse by removing `locationTaken` and relying on the DB constraint.
- A duplicate category is the same English name, ignoring case, among all rows (active or not).
- Editing a building's or floor's names changes only that one line's row, because each row stores its own copy; the form says so. See Follow-ups.
- An unknown language key gives `fields["name"] = "invalid"`, not a per-key code.
- Name inputs are labelled with the language picker's endonyms ("中文", not "中文(简体)").
- A failed save shows an error alert as well as field errors, so errors on copied building or floor names (which have no inputs on screen) are never silent.
