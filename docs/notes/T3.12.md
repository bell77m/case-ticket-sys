# T3.12 Harbor, signing, Kyverno

Date: 2026-09-29 · Requirements: NFR-10 · Agent: ops (main agent)

## What was done
- Harbor 2.15.2 (Helm chart 1.19.2, `deploy/platform/harbor-values.yaml`) runs behind the F5 NGINX Ingress with a certificate from the local CA. It has two private projects:
  - `ticket` for the app, migration and backup images;
  - `dockerhub` for signed copies of postgres, redis and gotenberg. These are copies, not a proxy cache: a proxied image could never carry our signature.
  Two robot accounts: `pull` (the node's containerd and Kyverno) and `ci` (push and sign).
- The Cosign key is Vault transit key `cosign` (ECDSA P-256). The private half never leaves Vault. A signer gets a 15-minute token with policy `cosign-sign`, which may only sign with that key and read its public half, and runs `cosign sign --key hashivault://cosign`. The public half is published as ConfigMap `kyverno/cosign-public-key`.
- Kyverno 1.19.1 (chart 3.9.1) enforces four CEL policies (`deploy/platform/policies`) on every Pod outside the platform namespaces:
  - `harbor-images-only`: every container, init container and ephemeral container image starts with the Harbor host;
  - `harbor-signed-images`: every Harbor image carries a Cosign signature from the Vault key, and the Pod is rewritten to the digest that was verified;
  - `require-non-root`;
  - `require-limits` (CPU and memory).
  ClusterPolicy is deprecated in 1.19 and goes in 1.20, so the new policy types are used.
- On the local cluster `make cluster-images` now builds, pushes and signs through Harbor (`deploy/local/push-images.sh`) instead of `k3d image import`, and the local overlay pulls everything from `harbor.localtest.me`. `make cluster-check-policies` proves the rules.

## Decisions
- Proven on the local k3s cluster, like T3.10–T3.16. Still to do on the T3.09 host:
  - Harbor's host name (`harbor.example.internal` is a placeholder in the base, the policies and `deploy/trivy-data.yaml`) and a company-CA certificate;
  - its secrets file written from Vault at install time;
  - the node's registries.yaml from the pull robot;
  - the same Vault transit setup, and the scan-all schedule (Trivy is on there).
- Third-party images are copied and signed, not proxied. To go back to a proxy cache, the signature policy would have to exempt project `dockerhub`, which lets unsigned images in.
- Signing is key-based with no transparency log (`--tlog-upload=false`, `insecureIgnoreTlog` in the policy): the key sits in a private Vault, and a public Rekor entry would publish internal image names.
- The platform namespaces (kube-system, kube-public, kube-node-lease, kyverno, harbor, nginx-ingress, vault, vault-secrets-operator-system, argocd) are left out by name, so any new namespace is covered by default. Moving a namespace in or out is one line in `deploy/platform/policies/kustomization.yaml`.
- The signature policy has autogen switched off and matches Pods only: rewriting a Deployment's image to a digest would make Argo CD see drift and undo it. A bad Deployment is still refused at Pod creation (its ReplicaSet shows the error).
- Only the latest transit key version is published. Rotating the key means signing every image again.
- Locally only the Kyverno admission controller runs, and Trivy is off, because Docker Desktop's VM has 7.4 GiB for everything.

## Checks
- `make cluster-check-policies`: 9/9 PASS.
  - Refused: an unsigned image and an image signed with another key (`harbor-signed-images`), a Docker Hub image (`harbor-images-only`), a root container (`require-non-root`), a container without limits (`require-limits`).
  - `kubectl debug` with a Docker Hub image and with an unsigned image: refused.
  - A signed image was admitted as `harbor.localtest.me/ticket/ticket-app:local@sha256:d2e5c6bd…`.
  - ticket-local runs 4 images, all from Harbor by digest.
- `make cluster-deploy` with the policies on: all six images pushed and signed. The migration Job completed and ticket-app rolled out, every Pod pinned to its verified digest.
- `make cluster-check-ingress`: 12/12 PASS. Its in-cluster curl pods now use a signed Harbor copy, non-root, with limits.
- `make cluster-restore-test` (T3.16) passes under the policies: checksums, age encryption, counts, evidence checksums, audit grants.
- The signature on the postgres copy verifies with plain `cosign verify --key cosign.pub` (the published public key). push-images.sh skips images signed already ("signed already: …redis@sha256:ac36b5c1…").
- `make deploy-lint`: kube-linter "No lint errors found!" and Trivy 0 misconfigurations for staging and prod.
- `/check`: go vet, `make test` (Go and i18n), golangci-lint 0 issues and svelte-check 0 errors all pass.
- Security review (harbor-setup.sh, push-images.sh, the policies, the vault-setup.sh block): 1 high and 1 medium, both fixed and proven by the `kubectl debug` checks:
  - ephemeral containers bypassed every policy, because the `pods/ephemeralcontainers` subresource was not matched;
  - the signature policy did not check ephemeral containers.
  No secret in argv, logs or Git; robot and Vault policies are least privilege.
- Found and fixed on the way:
  - `cosign verify --key hashivault://` calls Vault's `transit/verify`, so policy `cosign-sign` now allows verify (images were being signed twice);
  - a restart moved the node to another IP (see Decisions and CLAUDE.md);
  - Windows kubectl cannot read `/dev/stdin` in `--from-file`, so the scripts use temp files.
