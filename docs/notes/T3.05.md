# T3.05 PDF export

Date: 2026-09-27 · Requirements: FR-P4, FR-I6, FR-L1, FR-R3 · Agent: be + fe

## What was done
- Staff with report.view click "Export PDF" on /staff/reports and download `tickets-report-YYYY-MM-DD.pdf`. It shows the current view in the viewer's language: the period and filters, the 7 summary cards, the written summary, and the 7 graphs, each followed by its data table.
- `POST /api/staff/reports/export` validates the same filters as the dashboard. It stores them with the staff ID and language in Redis under a 60-second one-time token (only its SHA-256 is kept), then asks Gotenberg to print `PRINT_BASE_URL/print/report#<token>`. It sends the locale cookie and waits for `window.printReady`. `report.exported` is audited with the filters before the PDF is sent.
- `/print/report` is a chrome-free page. It reads the token from the URL fragment, loads the data once from `GET /api/print/report` (X-Print-Token), renders with chart animation off, waits for fonts, and sets `printReady`. The print endpoint needs no session, but re-checks that the staff member is still active and still holds report.view. Building and category names come back in the report's language.
- A print page that fails (expired token, network or render error) throws before setting `printReady`. Gotenberg is told `failOnConsoleExceptions`, so it refuses (409): the export answers 502 `pdf.failed`, and there is no PDF and no audit row.

## Decisions
- `GOTENBERG_URL` and `PRINT_BASE_URL` are optional: when unset, export answers 503 `pdf.unavailable` and the app still starts. They were NOT added to .env.example, which the agents cannot edit (a deny rule); see Follow-ups.
- The token travels in the URL fragment, so it never reaches server or proxy logs.
- A failed print is detected by throwing on the page plus `failOnConsoleExceptions`. On the real Gotenberg, throw-then-ready gives 409 in 0.5 s, while ready-then-throw lets the PDF through and never setting ready waits for the 30 s timeout.
- The Viewer exemption in TestStaffRoutes_FRR3 covers only the export POST, because it is a read of report data that Viewers may do.
- Vite binds 127.0.0.1 because on Windows it listened only on `::1`, which the container could not reach.
- Export body filters are strings, as in the dashboard's query.
