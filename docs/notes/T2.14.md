# T2.14 Security review, phases 1–2

Date: 2026-09-24 · Requirements: FR-R3, FR-A1–FR-A11, FR-L1, FR-L2, FR-G5, NFR-2, NFR-3, NFR-5 · Agent: security-reviewer + be

## What was done
- Five narrow security-reviewer passes, each on 4 files or fewer:
  - guest endpoints: tickets, track, lookup, routes
  - uploads and file serving: attachments, detail, web, main
  - RBAC and audit: rbac, audit, roles, actions
  - staff admin, queue and DB grants: staff, admin_lookup, queue, 00001_init.sql
  - auth: auth, limit, session, credentials
- The server now cuts off clients that trickle a request or hold idle connections: ReadTimeout 1 min, IdleTimeout 2 min, and header timeout 10 s as before. A guest's evidence upload extends its own read deadline to 15 minutes, but only after the tracking token is checked.
- Every response carries default security headers:
  - X-Content-Type-Options: nosniff
  - X-Frame-Options: DENY
  - Referrer-Policy: no-referrer
  - a CSP with frame-ancestors 'none', object-src 'none', base-uri 'self' and form-action 'self'

  Evidence downloads still replace the CSP with their sandbox policy.
- Each finding is fixed, accepted with a reason, or shown not to be a defect. The full list is under T2.14 in docs/PLAN.md.

## Decisions
- No script-src or style-src in the CSP yet. The SvelteKit build bootstraps with an inline script, so a strict policy needs `kit.csp` hashes and a full e2e run against the built app. Reverse: add both and extend TestSecurityHeaders.
- No WriteTimeout. Large evidence downloads and the planned server-sent events (T3.04) need long writes.
- Accepted, medium: Agent "self only" assignment is keyed to the role name. This is the T2.04 decision awaiting human review; custom roles with ticket.assign may assign anyone.
- Accepted, low: /api/track/* has no rate limit (256-bit tokens). An NGINX request limit is planned in T3.10.
